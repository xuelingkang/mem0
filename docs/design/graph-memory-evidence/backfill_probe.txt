## 读数说明（不是措辞，是口径）

| 现象 | 口径 |
| --- | --- |
| run 1：`processed=2` 而 `graph_episode_delta=2`、`edge_delta=2` | 计数与图内实际增量一致 |
| run 2/3：`processed=0 / already_synced=2`、两个 delta 均为 0、墙钟 13–15ms | 已入图的事实重复扫到时**零 LLM**（`/episodes` 的 `entity_edges` 判据），且确定性可复现 |
| 中断批次：`episodes` 2→5 而 `edges` 2→3 | 落库 3 个 episode 中 1 个完成抽取（有边），2 个被停容器打断（无边） |
| 续跑：`processed=4`、`already_synced=3`、`episodes` 5→7（delta 2） | 3 条有边的被跳过；4 条入图里 2 条是「空 episode 救援」（同 uuid 复用节点，故不新增 episode 节点），2 条是新事实。**episode 总数 7 = 7 条不同事实**，没有一条事实被入图两次 |
| `scope_total=26` → 31 | 并发实测用 `POST /memories` 又写了 5 条隔离事实（主链路写入 + 派发），回填的候选集随之增长 |
| `paced_wait_seconds=57.565`（rate=1）vs `0.0`（rate=0） | 限速生效：同样 2 条、同一作用域，墙钟 28.9s → 62.7s，差额几乎全在限速等待 |
| `facts_per_minute=1.914`（rate=1，2 条） | 批次内平均速率可略高于 `rate`：**首条不受限速延迟**（起始间隔闸门只约束相邻入图），小批次的尾条耗时落在分子里。长跑时收敛到 ≤ rate |
| `/search` 首测 `graph_status=timeout` | 回填与图派发共用同一 LLM 通道，图检索 1.0s 预算被占满时按设计降级（主链路仍 200、结果 5 条）；这正是限速存在的理由 |
| 清理：`qdrant_scope_count_after=0`、`graph_key_present_after=false` | 隔离记忆与图键已全额清除 |
| `mem0_xue` 129 → 133 episodes | 本探针未对 `xue` 发起任何回填；增长来自并发会话的正常增量写入（只读观测） |
