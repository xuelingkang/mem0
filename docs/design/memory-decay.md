# 1. 项目概述

## 1.1 背景

`/search` 当前按混合打分（语义相似度 + BM25 + 实体加权）排序，打分结果只取决于查询与文本内容的语义关系，与「这条记忆多久没被用到、被用到过多少次」无关。全库龄分布实测为：龄中位数 16.9 天、p95 23.8 天、最大 23.8 天（2026-09-17，3545 点）。同一批候选中，陈龄记忆与新鲜记忆同权竞争。

云平台 v3 把这一维度做成 Memory Decay：每条记忆带访问足迹，检索时把足迹换算成 0.3×–1.5× 的缩放因子乘进排序分，地板与天花板保证它「只重排、不淘汰」。

本方案为自托管 mem0 落地同一机制，模型取 Ebbinghaus 遗忘曲线，参数按本机语料标定。

## 1.2 目标

1. 每条记忆携带访问足迹：最后一次被召回的时间、累计被召回次数。
2. 检索打分引入时间因子：`final_score = similarity × decay_weight`，`decay_weight` 由足迹与龄共同决定。
3. 语义相似度保持主导：相似度相差达到阈值的一对候选，时间因子无法改变它们的相对次序；任何候选都不会因衰减被排除出候选集。
4. 被反复召回的旧记忆获得强度增长，在同样的龄下衰减更慢。
5. 全部能力可由一个开关关闭；关闭后的检索行为与引入本机制之前逐位一致。
6. 以上全部落在 Qdrant payload 上，不引入第二份存储。

## 1.3 范围

包含：

- `mem0/utils/scoring.py`：打分器接受时间因子。
- `mem0/memory/main.py`：衰减纯函数、检索路径的时间因子计算与强化写入触发、一等字段清单扩充。
- `mem0/configs/base.py`：检索衰减配置段。
- `mem0/vector_stores/qdrant.py`、`mem0/vector_stores/base.py`：payload 索引声明与批量足迹写入方法。
- `server/main.py`：配置默认值、REST 序列化与导出列。
- `tests/`：新增单测与端到端验证。

# 2. 需求分析

## 2.1 功能需求

| 编号 | 需求 |
| --- | --- |
| F1 | 每次 `/search` 返回结果后，为最终入选的每条记忆记录一次访问：`last_accessed` 更新为本次检索时刻，`access_count` 加一 |
| F2 | 检索打分把时间因子乘进分数：`final_score = similarity × decay_weight` |
| F3 | `decay_weight` 由记忆强度决定，强度随 `access_count` 增长 |
| F4 | `decay_weight` 的取值区间有下界且不含 0，任何候选都不会因衰减被排除或被清零 |
| F5 | 相似度相差达到阈值的候选对，次序不受时间因子影响 |
| F6 | 开关关闭时，`decay_weight` 恒为 1，检索结果与引入本机制之前完全一致 |
| F7 | 两个足迹字段是一等字段：单条读取、检索结果、导出与 CSV 表头中均可见 |
| F8 | 管理列表 `GET /memories`、导出、entity 列表的顺序与语义不受本机制影响 |

## 2.2 非功能需求

| 项 | 要求 |
| --- | --- |
| 额外 LLM 调用 | 零 |
| 检索读放大 | 候选池规模不变，打分阶段新增一次 O(n) 的纯算术与一次排序 |
| 写放大 | 每次 `/search` 至多一次批量 payload 写请求；写入只触及最终入选条目 |
| 写请求在线路径 | 强化写入不阻塞检索响应（异步派发），失败不改变检索结果 |
| 明文可观测 | 每条结果的分值构成（含时间因子）在 `explain=true` 时可见 |
| 幂等性 | 同一批条目重复强化只单调累加足迹，不改变其它字段 |
| 可复现 | `decay_weight` 为纯函数：同足迹同刻同输出，不依赖 LLM、不依赖网络 |

# 3. 衰减函数与参数

## 3.1 函数形式

Ebbinghaus 遗忘曲线（记忆强度 `S` 为时间常数）：

```text
R(Δt, S) = exp(-Δt / S)
```

| 符号 | 含义 | 单位 |
| --- | --- | --- |
| `Δt` | 自上次被召回起算的经过时间 | 天 |
| `S` | 该记忆的记忆强度 | 天 |
| `R` | 保留率，取值 (0, 1] | — |

`Δt` 的起点取该记录的 `last_accessed`；`last_accessed` 缺失时取 `created_at`（见 4.5）。

## 3.2 `S` 的更新公式

强度随累计召回次数线性增长，并设上限：

```text
S(n) = S₀ + ΔS · min(n, N_cap)
```

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `S₀` | 12 天 | 首次出现（`n = 0`）时的记忆强度 |
| `ΔS` | 3 天 | 每次被召回所增加的强度 |
| `N_cap` | 20 | 计入强度增长的召回次数上限 |

计数上限的作用：反复被召回的条目不会无限增长强度，越界后行为与恰好 20 次一致（与云平台「每个记忆最多保留最近 20 次触摸」的上限同量级）。

## 3.3 参数取值依据

**依据 A：函数形式与 `S` 的离散增长取自 MemoryBank。** 论文原文（arXiv 2305.10250 §2.3）：*"The Ebbinghaus forgetting curve is expressed using an exponential decay model: R = e^{−t/S} … we model S as a discrete value and initialize it with 1 upon its first mention in a conversation. When a memory item is recalled during conversations, it will persist longer in memory. We increase S by 1 and reset t to 0."* 本方案沿用「`S` 随召回离散增长、`Δt` 归零」这一形态；量级按本机语料重标（见依据 B）。

**依据 B：`S₀` 按本机全库龄分布标定。** 本机龄分布（实测，见第 10 节 E1）：

| 分位 | p0 | p25 | p50 | p75 | p95 | max |
| --- | --- | --- | --- | --- | --- | --- |
| 龄（天） | 0.00 | 10.17 | 16.91 | 21.17 | 23.82 | 23.83 |

约束：**全库中位龄（16.9 天）的记忆，其时间因子不得低于 0.92**（即中位龄记忆在正常竞争中只受轻微下调）。代入 `w̃ = 0.90 + 0.10·exp(−Δt/S₀)`，要求 `exp(−16.9/S₀) ≥ 0.2`，得 `S₀ ≥ 10.5`。取 `S₀ = 12`（半衰期 8.32 天），中位龄处 `w̃ = 0.9245`，满足约束并留有余量。

对照：PowerMem 以「1 小时后保留 44%」标定其衰减常数（`decay_constant = −ln 0.44`），该量级面向小时级学习场景；本机语料的龄尺度是天级，直接套用会让全库在一天内跌到地板，故不采用其常数、只采用其「按观测数据标定 + 设保留下限」的方法。

**依据 C：`ΔS` 与 `N_cap` 决定强化幅度。** 每次召回 `S` 提升 3 天：

| 召回次数 `n` | 0 | 1 | 5 | 20（上限） |
| --- | --- | --- | --- | --- |
| `S(n)`（天） | 12 | 15 | 27 | 72 |
| 半衰期（天） | 8.32 | 10.40 | 18.71 | 49.91 |

即：一条被反复召回的旧记忆，其半衰期从 8.3 天延展到 49.9 天——在被持续使用的场景下，它在两个月内基本不衰减。

**依据 D：权重区间由实测相似度结构确定（见 3.4 与 5.2）。**

## 3.4 权重归一化与取值区间

时间因子对**原始相似度**归一化，取值区间下界为 0.90：

```text
decay_weight = FLOOR + (1 − FLOOR) · R          FLOOR = 0.90
final_score  = similarity × decay_weight
```

| 参数 | 值 |
| --- | --- |
| `FLOOR` | 0.90 |
| 权重区间 | [0.90, 1.00] |
| 权重最大比 ρ | `1 / FLOOR = 1.1111` |

三个性质：

1. **不放大**：`decay_weight ≤ 1`，`final_score ≤ similarity`。陈旧记忆的分被下调，新鲜记忆的分等于其原始相似度——新记忆的相对优势来自旧记忆的下调，不来自任何上抬，因此语义分的地板永不被时间因子抬过。
2. **不为零**：下界 0.90（云平台形态下界 0.3×，本方案更保守），任何候选都不会因衰减被排除出候选集。
3. **有界**：任何两条候选的时间因子比值不超过 1.1111，这是 5.2「相似度为主」的硬边界来源。

标定表（`w̃` 为归一化后的时间因子）：

| Δt | n=0 | n=1 | n=5 | n=20 |
| --- | --- | --- | --- | --- |
| 1 小时 | R=0.997 w̃=0.9997 | R=0.997 w̃=0.9997 | R=0.998 w̃=0.9998 | R=0.999 w̃=0.9999 |
| 1 天 | R=0.920 w̃=0.9920 | R=0.936 w̃=0.9936 | R=0.964 w̃=0.9964 | R=0.986 w̃=0.9986 |
| 3 天 | R=0.779 w̃=0.9779 | R=0.819 w̃=0.9819 | R=0.895 w̃=0.9895 | R=0.959 w̃=0.9959 |
| 7 天 | R=0.558 w̃=0.9558 | R=0.627 w̃=0.9627 | R=0.772 w̃=0.9772 | R=0.907 w̃=0.9907 |
| 14 天 | R=0.311 w̃=0.9311 | R=0.393 w̃=0.9393 | R=0.595 w̃=0.9595 | R=0.823 w̃=0.9823 |
| 17 天 | R=0.243 w̃=0.9243 | R=0.322 w̃=0.9322 | R=0.533 w̃=0.9533 | R=0.790 w̃=0.9790 |
| 24 天 | R=0.135 w̃=0.9135 | R=0.202 w̃=0.9202 | R=0.411 w̃=0.9411 | R=0.717 w̃=0.9717 |
| 90 天 | R=0.001 w̃=0.9001 | R=0.002 w̃=0.9002 | R=0.036 w̃=0.9036 | R=0.287 w̃=0.9287 |

## 3.5 时间基准

- 一切时刻以 UTC 记录与比较；足迹字段写 ISO8601 带时区（与既有 `created_at` / `updated_at` 同形）。
- 比较用当前时刻 `now()` 由检索方注入一次（整批候选共用同一基准），同一次检索内所有候选的 `Δt` 基于同一 `now`，结果可复现。

# 4. 观测字段与写入路径

## 4.1 字段定义

Qdrant payload 顶层新增 2 个字段（与 `data` / `hash` / `created_at` / `valid_at` 同级）：

| 字段 | 类型 | 语义 | 写入时机 |
| --- | --- | --- | --- |
| `last_accessed` | ISO8601 字符串 或 缺失 | 该记忆最后一次被检索返回的时刻 | 每次 `/search` 返回后，对最终入选条目批量写入 |
| `access_count` | 整数 或 缺失 | 该记忆累计被检索返回的次数 | 与 `last_accessed` 同批写入，单调累加 |

字段形态约定：缺失等于「从未被检索返回过」，与「已赋值为 0」在语义上等价（见 4.5）。

## 4.2 强化的定义

一次「访问」= 该记忆出现在一次 `/search` 的最终返回列表中。被检索到但未进入返回列表（候选池内被截断）不产生强化。这与云平台的语义一致（对每条返回的记忆记录一次强化），也是本机唯一可得、且不引入额外链路的访问信号。

已知语义边界：返回不等于被用户实际采纳。检索方（Hermes 记忆注入）每轮调用一次 `/search`，因此「一轮对话中被召回到」即记为一次访问。

## 4.3 写放大控制

采用四项联合控制，缺一不可：

| 控制 | 具体形态 |
| --- | --- |
| 仅对最终入选条目更新 | 强化对象是打分与截断之后的返回列表（至多 `top_k` 条），候选池内其余条目不动 |
| 批量化 | 一次检索的全部强化目标合并为**一个** Qdrant 批量 payload 写请求 |
| 节流 | 进程内维护 `memory_id → 上次写入时刻` 表，同一记忆在冷却窗口（默认 300 秒）内只写一次；冷却窗口内的重复命中不累加计数 |
| 异步落盘 | 强化在检索响应返回之后派发（后台线程），不进入响应时延路径；写入失败只记日志，不影响已返回的结果 |

写入形态为 payload-only 更新：`vector=None`，只更新 `last_accessed` / `access_count` 两个键。Qdrant 侧对应 `set_payload` 语义——**向量与 BM25 稀疏向量不重算、`data` / `hash` / `created_at` / `valid_at` 等字段逐字不变**（第 10 节 E6 为隔离集合上的实测证据）。

## 4.4 写频次估算

实测输入（第 10 节 E3、E9）：

| 项 | 实测值 |
| --- | --- |
| `/search` 调用量（14 天） | 1582 次 → 113.0 次/天 |
| `/search` 调用量（7 天） | 938 次 → 134.0 次/天 |
| 检索平均时延 | 676 ms |
| 命中集重合度（20 次查询 × `top_k=10`） | 200 次命中 / 195 个唯一 id → 重复率 2.5% |
| 现状 Qdrant 新增点 | 近 7 天 520 点 → 74.3 点/天 |

按 `top_k=10`、134 次/天计算：

| 项 | 估算 |
| --- | --- |
| 强化命中次数/天 | 134 × 10 = 1340 |
| 强化写请求/天 | ≤ 134（每次检索 1 个批量请求）≈ 0.09 次/分钟 |
| 被触及的唯一点/天 | 上界 1340；按实测命中重复率（`top_k=10` 时 2.5%）折算 ≈ 1306 |
| 节流窗口后的点触及量 | 14 天内有 577 个互不重叠的 300 秒窗口（vs 1582 次检索），冷却 300 秒把同一记忆的重复触及压缩到「每 5 分钟至多一次」；窗口内该记忆的后续命中不再产生写入 |
| 命中重复率随 `top_k` 的变化 | `top_k=10` 时 2.5%（200 次命中 / 195 唯一）；`top_k=50` 时 13.8%（1000 次命中 / 862 唯一） |
| 与现状落库写入之比 | 写请求 ≤134/天 vs 新增点 74/天；写入体量为 payload-only（无向量、无 BM25） |

结论：检索侧写请求量（≤134 次/天，约 0.09 次/分钟）与现有写入路径同量级，写入体量小于现有新增点路径（后者每次写入含 2048 维稠密向量与 BM25 稀疏向量）。

## 4.5 存量记录语义

判定结论：**存量记录不回填足迹，直接参与打分。**

| 情形 | `Δt` 起点 | `n` | 结果 |
| --- | --- | --- | --- |
| 有 `last_accessed` | `last_accessed` | `access_count` | 正常衰减曲线 |
| 无 `last_accessed`，有 `created_at` | `created_at` | 0 | 从入库时刻起算、按未强化衰减 |
| 两者皆缺 | `Δt = 0` | 0 | 时间因子 = 1（中性，不影响排序） |

依据（第 10 节 E1）：全库 3545 条全部具备 `created_at`，`last_accessed` / `access_count` 命中数均为 0；因此上线首日全库走第二行语义，全库时间因子分布落在 [0.9185, 1.0000]（实测：min 0.9185、p25 0.9241、p50 0.9369、p75 0.9724）。

不做回填的理由与阶段 1 的 `valid_at` 同理：**`created_at` 是存量记录唯一真实可信的「上次使用」证据**；写入推测值等于伪造一条访问历史，且会让「从未被召回」与「很久以前被召回」两种不同状态不可区分。云平台对 decay 上线前的存量记忆同样采用「无足迹 → 用事件时间兜底」的降级路径。

后续行为：新写入记录在首次被检索返回时获得足迹；存量记录在被检索返回后自然积累足迹，此后与其它记录行为一致。

# 5. 排序融合

## 5.1 融合位置与公式

时间因子在混合打分阶段融合，即 `score_and_rank` 内部、`threshold` 过滤与 `top_k` 截断之前：

```text
final_score = similarity × decay_weight
```

| 层 | 现状 | 本方案 |
| --- | --- | --- |
| 语义候选池 | `max(top_k × 4, 60)` 条（`_search_vector_store` Step 3） | 不变 |
| `threshold` 过滤 | 按语义分过滤 | 不变（在时间因子之前） |
| 混合打分 | `(semantic + bm25 + entity) / max_possible` | 不变 |
| 时间因子 | — | 对混合分乘以 `decay_weight` |
| 排序与截断 | 按混合分降序取 `top_k` | 按 `final_score` 降序取 `top_k` |

候选池规模不改，`top_k` 截断仍在最后；时间因子只能在已进池的候选之间重排。

层序关系（`Memory.search` 内的实际顺序）：`_search_vector_store`（含时间因子）→ 可选 rerank → 返回。当前配置下未启用 reranker，时间因子即为最终序；若日后启用 reranker，reranker 在其后按自身相关性重排。

作用范围：仅 `/search` 路径。写入管道的 Phase 1 候选检索（`_add_to_vector_store` 内的 `vector_store.search`）不经打分器，不引入时间因子——该检索是 1a 去重与 1b 矛盾检测的候选来源，与「何时被用过」无关。

## 5.2 「相似度为主、衰减为辅」的论证

**硬不变量（可判定、与数据无关）：**

设两条候选的原始相似度分别为 `s₁ > s₂`。时间因子有界 `decay_weight ∈ [0.90, 1.00]`，故

```text
s₁/s₂ ≥ 1/0.90 = 1.1111  ⟹  s₁·w₁ ≥ s₁·0.90 ≥ s₂·1.00 ≥ s₂·w₂  ⟹ 次序不变
```

即：**原始相似度相差 11.11% 以上的一对候选，时间因子无法翻转其相对次序。** ρ = 1.1111 是模型的硬边界，不随语料变化。

**实测对照（20 条真实查询 × `top_k=50`，见第 10 节 E2/E4）：**

| 指标 | 实测 |
| --- | --- |
| 候选池内首尾相似度比 `s_top / s_last` | min 1.152 / median 1.406 / max 1.566 |
| 相邻候选相似度比 | median ≈ 1.005，max 1.149 |
| 相邻比达到 ρ（≥1.1111）的占比 | 2 / 380（`top_k=20` 全量相邻对）；全语料最大相邻比 1.1488 |
| 候选对中相似度比 ≥ ρ（免疫重排）的比例 | median 23.2% |
| 实测发生翻转的对 | median 7.4%（占全部候选对） |
| 翻转对的相似度比上界 | max 1.0897 |

最后两行是本模型的关键证据：**所有实际发生的翻转，其相似度比都小于 ρ（1.0897 < 1.1111）**，即翻转只发生在「相似度几乎相同」的近邻带内。相似度差超过 11% 的候选对在实测中保持了原有次序。

**重排强度实测（同上）：**

| 指标 | 实测 |
| --- | --- |
| `top_k=10` 返回集的保留率 | median 90%，min 40% |
| `top_k=10` 换入条数 | median 2，max 12 |
| 排序保序性（`top_k=20` 内 Kendall τ） | median 0.816 |
| 共同项最大位次位移 | median 15，max 41（在 `top_k=50` 池内） |

即：衰减确实改变排序（返回集平均换入 2 条），但保序性维持在高位（τ ≈ 0.82），且不存在「时间主导」的极端——时间因子最大只能把一条候选挪过相似度比小于 1.111 的邻居。

**地板取值的过程依据**（在 S₀=12 / ΔS=3 / N_cap=20 下，对同一实测语料扫描 `floor`）：

| floor | ρ | `top_k=20` τ | `top_k=10` 换入（med/max） | 全对翻转率 | 免疫率 | 翻转对的相似度比上界 |
| --- | --- | --- | --- | --- | --- | --- |
| 1.00（等效关闭） | 1.000 | 1.000 | 0 / 0 | 0.00% | 100.0% | — |
| 0.95 | 1.053 | 0.916 | 2 / 4 | 4.04% | 48.7% | 1.0426 |
| 0.92 | 1.087 | 0.853 | 2 / 12 | 5.88% | 29.8% | 1.0720 |
| **0.90（选用）** | **1.111** | **0.816** | **2 / 12** | **7.43%** | **23.1%** | **1.0897** |
| 0.85 | 1.176 | 0.747 | 4 / 14 | 11.43% | 12.2% | 1.1426 |
| 0.80 | 1.250 | 0.684 | 5 / 14 | 15.39% | 5.7% | 1.1931 |

取 0.90 的理由：免疫率（相似度比 ≥ ρ、次序不可被翻转的候选对占比）仍有 23.1%，保序性 τ 保持在 0.816 的高位；再往下压（0.85 / 0.80）免疫率迅速跌到 12% / 5.7%，时间因子开始对多数相似度不等的对产生作用。

该表还有一项跨行成立的性质：**每一行的翻转对相似度比上界都小于该行的 ρ**（如 0.90 行 1.0897 < 1.1111，0.80 行 1.1931 < 1.2500）。即无论把地板调到哪一档，实际发生的翻转始终被约束在 ρ 以内的近邻带——ρ 是模型的硬边界，不依赖参数选择。

选用「只下调」形态（`decay_weight ≤ 1`）而非对称放大形态：前者满足 `final_score ≤ similarity`，使「语义分不被时间抬过」成为结构性保证而非调参结果。代价是新鲜记忆不获得额外加成——其位次优势来自旧记忆的下调。

## 5.3 返回契约

| 位置 | 变化 |
| --- | --- |
| 结果 `score` | 返回 `final_score`，保持既有 [0, 1] 区间（`decay_weight ≤ 1`，乘积不会越界） |
| 结果 `score_details`（`explain=true`） | 新增 `decay_weight`、`retention`、`memory_strength_days`、`elapsed_days`、`access_count` 五项 |
| `threshold` 语义 | 按原始语义分过滤，过滤发生在时间因子之前；返回的 `score` 可能略低于请求 `threshold`（被下调所致），此为预期行为 |
| 结果排序 | 按 `final_score` 降序 |

# 6. 开关与回退

## 6.1 开关

配置项落在 SDK 配置层（`MemoryConfig` 新增 `decay` 段），默认由环境变量驱动，服务侧沿用既有 `DEFAULT_CONFIG` 通道：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `enabled` | `false` | 衰减总开关；关闭时时间因子恒为 1，且不产生任何强化写入 |
| `halflife_days` | 12 | `S₀`（天） |
| `strength_step_days` | 3 | `ΔS`（天） |
| `access_cap` | 20 | `N_cap` |
| `floor` | 0.90 | 时间因子下界 |
| `cooldown_seconds` | 300 | 同一记忆的强化冷却窗口 |

## 6.2 回退语义

关闭开关后：时间因子为常量 1，`final_score = similarity × 1`；强化写入被整体跳过（不写 `last_accessed` / `access_count`）。已有的足迹字段保留在 payload 中不被清除，重新开启后继续累加。

实测证据（第 10 节 E5）：在真实语料上把权重区间设为 [1.00, 1.00] 重跑，`top_k=10` 换入条数为 0、全对翻转率 0.00%、Kendall τ = 1.000——逐位一致。

## 6.3 参数调优

全部参数可由环境变量覆盖，调整时不需要改动代码：

| 调优方向 | 调整项 | 效果 |
| --- | --- | --- |
| 想让陈旧记忆更快下沉 | 降低 `halflife_days` 或降低 `floor` | 重排强度上升、语义保序性下降（见 5.2 扫描表） |
| 想让常被召回的记忆更稳固 | 提高 `strength_step_days` 或 `access_cap` | 强化收益上升 |
| 想降低写频次 | 提高 `cooldown_seconds` | 同一记忆的单位时间写入次数下降 |

# 11. 验收标准

判定一律以**实现后的实际执行输出**为准，与具体 commit 对照，不认「工作区当下状态」。全部端到端验证使用隔离 `user_id`（`test_decay_*` 前缀），验证后清理。

## 11.1 衰减函数与参数

| 编号 | 验收内容 | 判定方式 |
| --- | --- | --- |
| [AC-1] | 衰减纯函数实现 `R = exp(-Δt/S)`、`S = S₀ + ΔS·min(n, N_cap)`：以 `S₀=12, ΔS=3, N_cap=20` 调用，返回的 `retention` 与 `exp(-Δt/12)` 在 1e-9 内相等；`access_count=1` 时与 `exp(-Δt/15)` 相等；`access_count=25` 时与 `access_count=20` 结果相等 | 单测：固定 `now` 与固定足迹入参，断言数值 |
| [AC-2] | 时间因子落在 [0.90, 1.00]：`Δt=0` 时为 1.0000；`Δt=10000` 天且 `n=0` 时为 0.9000（不低于下界） | 单测：两端点断言 |
| [AC-3] | 函数是纯函数且不接触外部依赖：同一入参调用两次结果按 `repr` 相等；函数签名不含 llm / client / 网络参数；两次调用之间不产生任何写操作 | 单测 + 函数签名检查 |
| [AC-4] | 时间基准为 UTC：同一 `now` 下，带不同时区偏移的等价时刻（如 `+08:00` 与 `Z` 的同一瞬间）得出相同 `elapsed_days`（误差 < 1e-6 天） | 单测：两个等价时间串断言语等 |
| [AC-5] | 权重参数可由配置覆盖：以非默认 `halflife_days` / `strength_step_days` / `access_cap` / `floor` 构造实例，`decay_weight` 随新参数变化，且 `floor` 变化时下界随之改变 | 单测：两组配置对比 |

## 11.2 排序融合（真实 HTTP，隔离 `user_id`）

| 编号 | 验收内容 | 判定方式 |
| --- | --- | --- |
| [AC-6] | **衰减确实生效**：构造一组候选（≥5 条），其中两条语义相似度接近（比 < 1.111）而龄与访问次数不同，开启衰减后返回序与关闭时的返回序不同 | 隔离 `user_id` 各写一组记忆 → 同一 query 在开关两种状态下各跑一次 `POST /search` → 对比 id 序 |
| [AC-7] | **相似度语义未被破坏（硬不变量）**：构造一对候选，其语义相似度比 ≥ 1.1111，开启衰减后二者的相对次序与关闭时一致；对真实语料上 20 条 query × `top_k=50` 全对扫描，不存在相似度比 ≥ 1.1111 而被翻转的对 | 隔离构造用例 + 真实语料扫描脚本（`explain=true` 取原始语义分） |
| [AC-8] | 高相似度的新记忆仍能压过低相似度的旧记忆：构造「新写、相似度 0.70」与「20 天前、相似度 0.60」两条，开启衰减后新记忆排在前 | 隔离 `user_id` 端到端 |
| [AC-9] | 常被召回的旧记忆优于同龄未强化的旧记忆：两条同 `created_at`、同语义分的记忆，其中一条 `access_count` 较大，开启衰减后它排在前 | 隔离 `user_id`：写入后直接改 payload 构造足迹差异 |
| [AC-10] | 衰减不为任何候选带来放大：同一 query、同一 `top_k` 下，开启状态每条结果的 `score` 都 ≤ 关闭状态同一条的 `score`，且比值 ≥ 0.90 | 开关两态对同一 query 逐条比对 `score` |
| [AC-11] | 衰减只重排、不淘汰：把 `top_k` 取得足够大（等于候选池规模，如 50），同一 query 下开启与关闭两种状态返回的 id **集合完全相同**，仅顺序不同 | 端到端两种状态对比 id 集合 |
| [AC-12] | `explain=true` 时每条结果的 `score_details` 含 `decay_weight` / `retention` / `memory_strength_days` / `elapsed_days` / `access_count` 五个键 | 读取响应 JSON 的键集合 |
| [AC-13] | `threshold` 语义不变：过滤按原始语义分，在时间因子之前发生；被判定的候选数量在开关两态下相同 | 端到端对比 `explain` 的 `threshold` 与结果条数 |

# 12. 实现卡拆分建议

改动集中在 SDK 检索路径与配置层，链路串行（打分器 → 检索路径 → 配置 → 服务层），建议按一张卡串行实现。可在同一张卡内并行的两块：

| 分块 | 内容 | 依赖 |
| --- | --- | --- |
| A 打分与融合 | `scoring.py` + `main.py` 的衰减纯函数、检索路径、强化触发 | 无（可先做） |
| B 存储与配置 | `base.py` 配置段、`qdrant.py` 批量写入与索引、`server/main.py` 序列化与导出 | 无（可先做） |

合并顺序建议：A 与 B 分别可独立编译与单测；端到端验收（11.2 / 11.3）依赖两者同时就位。核验卡在其后独立复跑。

# 13. 附录

## 附录 A：术语表

| 术语 | 含义 |
| --- | --- |
| 记忆强度 `S` | 遗忘曲线的时间常数（天），随累计召回次数增长 |
| 保留率 `R` | `exp(-Δt/S)`，取值 (0, 1] |
| 时间因子 `decay_weight` | `0.90 + 0.10·R`，乘进相似度的系数，取值 [0.90, 1.00] |
| 足迹字段 | `last_accessed` / `access_count` |
| ρ | 时间因子的最大比值 `1/floor = 1.1111`，相似度比达到该值即免疫重排 |
| 强化 | 记忆被一次检索返回，足迹累加一次 |
